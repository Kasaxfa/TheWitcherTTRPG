# Кодекс ремесленника — НРИ «Ведьмак»

Интерактивный справочник рецептов алхимии и ремесленных чертежей.

В каталоге 147 рецептов: 22 формулы алхимии, 60 чертежей оружия, 51 чертёж брони и 14 схем компонентов. У каждой записи указана страница основной книги правил. Формулы показаны символами алхимических групп и доступны также текстом.

## Запуск

Сайт статический. Откройте index.html в браузере. GitHub Pages может публиковать файлы из ветки main, папки /(root).

## База каталога

SQLite-база в database/catalog.sqlite3 хранит предметы, рецепты, составы, источники и подтверждённые свойства. Сейчас это 252 предмета: 106 ингредиентов (включая 68 конкретных алхимических субстанций и девять обозначений групп), 13 материалов, 60 видов оружия, 51 вид брони и 22 алхимических средства. У рецептов и предметов постоянные ID. Вес/стоимость подтверждены для 243 физических предметов; девять обозначений алхимических групп не являются предметами с массой и намеренно имеют `NULL`. Для каждого заполненного свойства предмета указана страница книги.

Для экспорта данных из SQLite в data.js выполните:

    python3 tools/build_catalog.py

Файл data.js — статический JSON-совместимый вывод из базы, который использует сайт. Там же экспортируются девять условных символов со страницы 142; порядок и количества символов в каждой формуле берутся из строк ингредиентов. При изменении базы сначала запустите эту команду, затем сохраните в Git и базу, и data.js.

Схема version 1 находится в database/schema.sql, а дальнейшие изменения — в database/migrations/. Команда экспорта применяет недостающие миграции по порядку в транзакциях. Если база отсутствует, восстановите файл из Git; старый снимок database/seed_recipes.json хранится для сверки первоначальных 147 рецептов и больше **не используется для пересборки**: такая операция уничтожила бы добавленные карточки и постоянные ссылки. Новым предметам и рецептам назначайте однажды созданный UUID, не вычисляя ID из имени, страницы или позиции. При объединении дублей старый ID сохраняется в `item_id_aliases`: при импорте будущего инвентаря сначала разрешайте его в текущий ID. Для внесения сверенных с книгой значений используется database/verified_items.json (поле `item_id` и напечатанная страница) и команда:

    python3 tools/import_verified_items.py

При изменении уже сохранённого поля вручную обновляйте источник значения в `item_field_sources` либо `source_id/source_page` для характеристики или эффекта. Если два предмета имеют одинаковое название, выбор в строке рецепта нужно явно закрепить в `ingredient_link_decisions`.

Проверка целостности:

    python3 tools/build_catalog.py --check

Для сверки 22 формул по символам, устойчивости ID при переименовании и связности каталога:

    python3 -m unittest discover -s tests -v

Проверка отклонит пропущенные миграции, ошибки внешних ключей, неоднозначные связи без решения и заполненные значения без страницы источника. В `database/verified_items.json` отсутствующие сведения опущены намеренно. Аббревиатуры доступности и свойства снаряжения переписаны из таблиц на стр. 73–90, материалы — со стр. 128–129, вещества — со стр. 143–145. Алхимические эффекты пересказаны по стр. 87–88. Заголовки чертежей также сверены с таблицами на стр. 130–139; это не заменяет построчную независимую проверку всех чисел и 714 строк компонентов.

Личные инвентари не записываются в общую SQLite-базу сайта. Для статического GitHub Pages они будут сохраняться в браузере и переноситься отдельным JSON-файлом.

## Публикация через GitHub Pages

В репозитории откройте Settings → Pages, выберите Deploy from a branch, затем ветку main и папку /(root).
