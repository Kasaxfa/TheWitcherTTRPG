# Кодекс ремесленника — НРИ «Ведьмак»

Интерактивный справочник рецептов, предметов, снаряжения и личного инвентаря.

Каталог разделён на алхимические формулы и ремесленные чертежи. Формулы показаны символами алхимических групп и доступны также текстом.

## Запуск

Сайт статический. Откройте index.html в браузере. GitHub Pages может публиковать файлы из ветки main, папки /(root).

Кнопка в шапке переключает светлую и тёмную тему. Выбранная тема сохраняется в браузере; при первом открытии используется светлая.

## База каталога

SQLite-база в database/catalog.sqlite3 хранит предметы, рецепты, составы, источники и подтверждённые свойства. Каталог содержит 350 записей: 110 ингредиентов (включая 68 конкретных алхимических субстанций и девять обозначений групп), 13 материалов, 60 видов оружия, 51 вид брони, 22 алхимических средства, 85 предметов снаряжения и 9 скакунов и транспортных средств. Снаряжение включает наборы инструментов, обычные вещи, контейнеры, еду и напитки, одежду и упряжь. У рецептов и предметов постоянные ID. Для 340 физических предметов указаны вес и цена; у Призрачной пыли вес в книге не приведён, а девять обозначений алхимических групп не являются предметами и намеренно имеют `NULL`.

Для экспорта данных из SQLite в data.js выполните:

    python3 tools/build_catalog.py

Файл data.js — статический JSON-совместимый вывод из базы, который использует сайт. Он содержит предметы с характеристиками и эффектами, рецепты с ценами, постоянными ID, входными и выходными связями по ID, символы алхимии и таблицу старых ID для объединённых предметов. Страницы и источники остаются в SQLite для сверки и не попадают в публичный файл. Девять символов взяты со страницы 142; их порядок и количество в формулах берутся из строк ингредиентов. Команда `--check` сверяет экспорт с базой, включая цены, свойства и все ссылки.

Схема version 1 находится в database/schema.sql, а дальнейшие изменения — в database/migrations/. Команда экспорта применяет недостающие миграции по порядку в транзакциях. Если база отсутствует, восстановите файл из Git; старый снимок database/seed_recipes.json хранится для сверки первоначальных 147 рецептов и больше **не используется для пересборки**: такая операция уничтожила бы добавленные карточки и постоянные ссылки. Новым предметам и рецептам назначайте однажды созданный UUID, не вычисляя ID из имени, страницы или позиции. При объединении дублей старый ID сохраняется в `item_id_aliases`: при импорте будущего инвентаря сначала разрешайте его в текущий ID. Для внесения сверенных с книгой значений используется database/verified_items.json (поле `item_id` и напечатанная страница) и команда:

    python3 tools/import_verified_items.py

При изменении уже сохранённого поля вручную обновляйте источник значения в `item_field_sources` либо `source_id/source_page` для характеристики или эффекта. Если два предмета имеют одинаковое название, выбор в строке рецепта нужно явно закрепить в `ingredient_link_decisions`.

Проверка целостности:

    python3 tools/build_catalog.py --check

Для сверки 22 формул по символам, устойчивости ID при переименовании и связности каталога:

    python3 -m unittest discover -s tests -v

Проверка отклонит пропущенные миграции, ошибки внешних ключей, неоднозначные связи без решения и заполненные значения без источника. В `database/verified_items.json` сведения, которых нет в книге, опущены. Перепроверены все 147 рецептов, их цены и 718 строк компонентов, а также каталог ингредиентов, оружия, брони и алхимических средств. Страницы источника нужны только для внутренней проверки базы и не показываются посетителям сайта.

## Разделы сайта

В разделе «Рецепты» доступны поиск по названию и компонентам, выбор алхимии или ремесла, выпадающие категории ремесла, фильтр уровня, цены и алхимические символы. Каталог «Предметы» ищет сразу по всем словам запроса в названии, описании, свойствах и эффектах; ингредиенты можно отфильтровать по доступности и алхимической группе, снаряжение — по категории, а скакунов и транспорт — по отдельному типу. В карточках показываются вес, цена, доступность, места поиска, характеристики и эффекты.

В разделе «Персонажи» отображаются карточки отдельных листов. Поиск работает по имени, игроку, расе и профессии; из карточки можно открыть, скопировать, переименовать, экспортировать или удалить персонажа. Удаление требует подтверждения, а удаление последнего персонажа заблокировано. Копия получает новые ID, исходные данные и инвентарь остаются независимыми. Одно-персонажный JSON добавляется в список; JSON с несколькими персонажами заменяет список только после подтверждения. Каждый лист имеет постоянный `characterId`, `schemaVersion`, `rulesVersion`, личные данные, жизненный путь, характеристики, навыки, текущее состояние, способности, снаряжение и заметки. Изменения сохраняются в браузере автоматически; после перезагрузки страницы данные восстанавливаются. На телефоне карточки идут одной колонкой. В «Инвентаре» выбранного персонажа считается вес по количеству и весу единицы, задаётся грузоподъёмность и редактируется вес. Предметы добавляются через поиск по названию; одинаково названные записи можно различить. Скакуны, транспорт и символические алхимические группы не предлагаются как переносимые предметы. Предметы с неизвестным весом не считаются как нулевые — для них отображается предупреждение.

Новый персонаж создаётся мастером из четырёх шагов: выбор расы, профессии и возраста; ручная или случайная предыстория; броски 9d10 с перебросом значений 1–2 или распределение 60/70/80 очков характеристик; закупка навыков кнопками или ручным вводом. Профессиональный пакет состоит из 11 навыков и использует 44 очка; остальные навыки используют бюджет Интеллекта и Реакции, а сложные навыки стоят вдвое больше. Случайная предыстория сохраняет результаты бросков, события по десятилетиям и связанных персонажей с пустыми полями имён. Расовые модификаторы отображаются отдельно от введённых характеристик и учитываются в итогах. У каждой профессии есть отдельное дерево способностей: следующий узел ветви открывается с рангом 0, когда предыдущий достигает 5.

В листе персонажа все навыки сразу видны в компактных группах по ведущей характеристике. Нажатие на характеристику или навык открывает настройки исходного значения либо постоянных и временных модификаторов; ранг навыка меняется во вкладке «Развитие». Общие навыки остаются в своих группах, а навыки стартового набора помечены. Узлы профессионального дерева выделены цветом; карточки показывают ранг, описание и статус блокировки. Улучшения в «Развитии» сначала попадают в черновик: их можно уменьшить или отменить, а кнопка «Применить прокачку» фиксирует распределение. Применённые очки нельзя вернуть и перераспределить. Новый ранг навыка стоит текущий ранг (первый — 1, сложный навык ×2), характеристика — текущее исходное значение ×10; обычный предел характеристики — 10. После открытия ветви можно продолжать улучшать любой её узел до ранга 10.

Во вкладке «Бой» ведутся текущие ПЗ, Выносливость, Удача и репутация, состояния и ранения по зонам, броня в шести зонах, основное и запасное оружие и щит. При назначении брони прочность по зоне берётся из карточки, если она там указана; текущее SP и повреждения можно менять отдельно. EV надетой брони суммируется по предметам и вычитается из Реа, Лвк и магических навыков согласно проверенному правилу; EV можно задать вручную для предмета. Если значение неизвестно, приложение показывает это и не считает его нулём. Штрафы ранений и состояний назначаются вручную. Кнопка начала сессии восстанавливает Удачу до текущего значения характеристики.

Каталог связан с листом: из рецепта можно открыть ингредиент или результат, из карточки предмета — связанные рецепты, а из инвентаря — карточку предмета. У предмета персонажа отдельно хранятся количество, вес, состояние и ручной EV. Повторное добавление предмета каталога увеличивает существующее количество; флажок «Отдельная запись» оставляет новый экземпляр самостоятельным. Удаление предмета снимает его из боевых слотов, не оставляя битых ссылок.

Во вкладке «Способности» можно вести известные заклинания, знаки, инвокации, порчи, ритуалы и алхимические записи. Для каждой записи доступны стоимость, дальность, длительность, время, СЛ, компоненты, эффект и заметки; запись можно связать по ID с предметом или рецептом каталога и открыть связанную карточку. В текущей базе нет полного отдельного справочника магических способностей, поэтому их сведения вносятся вручную и не выдаются за автоматически сверенный список книги.

Кнопка «Экспорт списка» сохраняет JSON-копию коллекции, а в меню каждой карточки доступен экспорт одного персонажа. Импорт проверяет версию формата, обязательные поля, числовые значения, уникальность ID и ссылки между событиями предыстории, предметами инвентаря и боевыми слотами; более новая или некорректная версия не перезаписывает сохранение. Последовательные миграции схемы v1 → v8 сохраняют данные, ранения, магические записи, боевые слоты и журнал черновых очков улучшения. Перед заменой коллекции прежние данные сохраняются в браузере. Старый одиночный инвентарь автоматически переносится в «Персонаж 1»; исходная запись остаётся в прежнем хранилище и включается в JSON-копию. Старый JSON только с инвентарём можно загрузить отдельно — он добавится отдельным персонажем. Хранилище остаётся локальным для браузера и устройства; для переноса или защиты от очистки данных скачивайте резервную копию.

## Публикация через GitHub Pages

В репозитории откройте Settings → Pages, выберите Deploy from a branch, затем ветку main и папку /(root).
