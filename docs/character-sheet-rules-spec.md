# Спецификация листа персонажа: НРИ «Ведьмак»

Статус: проект спецификации; расчёты со статусом «ожидает сверки» нельзя включать в автоматический расчёт до проверки по используемому русскому изданию.

## 1. Границы правил

- Система: The Witcher Tabletop Roleplaying Game от R. Talsorian Games. Лист не использует характеристики, классы, КД или уровни D&D.
- Базовый источник полей: официальный четырёхстраничный [Witcher Character Sheet](https://rtalsoriangames.com/wp-content/uploads/2018/08/witcher-character-sheet.pdf).
- При расхождениях между ранней печатью и правилами применяются поправки [официальной errata для 1-й и 2-й печати](https://rtalsoriangames.com/wp-content/uploads/2022/03/RTG-WI-WitcherCoreErratav4.pdf) и официальные уточнения разработчика. Перед выпуском надо подтвердить, что русский экземпляр пользователя соответствует этой редакции.
- Книга в доступной рабочей копии повреждена: PDF не открывается и не содержит читаемых страниц. Поэтому точные строки таблиц и формулы ниже помечены статусом. До получения читаемых страниц 20–70 незакрытые расчёты остаются ручными.

## 2. Поля листа

| Блок | Поля | Способ ввода / изменения |
|---|---|---|
| Персонаж | Имя, игрок, раса, пол, возраст, социальное положение, репутация | Ввод игроком; текст и числовые шкалы не нормализуются без правила книги |
| Жизненный путь | Происхождение, события жизни, отношения, стиль и личность, заметки кампании | Ручной ввод или выбор результата таблицы; значения должны сохранять источник выбора (бросок/решение игрока) |
| Профессия | Профессия, определяющий навык, профессиональное умение, очки обучения, очки улучшения | Профессия задаёт доступные профессиональные данные; очки развития меняются по ходу кампании |
| Характеристики | INT, REF, DEX, BODY, SPD, EMP, CRA, WILL, LUCK | Девять основных характеристик. Начальные значения вводятся по выбранному способу создания; повышение, расовые особенности и мутации должны храниться отдельно от базового значения |
| Навыки | Навыки, сгруппированные по ведущей характеристике; рейтинг каждого навыка | Рейтинг вводится и развивается игроком; видимые бонусы от происхождения, брони и способностей показываются отдельно |
| Производные показатели | STUN, RUN, LEAP, HP, STA, ENC, REC, Punch, Kick, Bonus Melee Damage, Vigor | Расчёт или таблица — см. раздел 3. Vigor задаётся профессией/правилом и не выводится из BODY или WILL |
| Текущее состояние | Текущие HP, STA и LUCK; ранения; состояния; потраченные ресурсы; текущие значения брони и надёжности | Меняется во время игры. Не сбрасывается при перезагрузке страницы; сброс LUCK выполняется только действием «Начать сессию» |
| Броня | Предмет, зоны тела, SP по зонам, текущая прочность/повреждение, EV, эффекты и сопротивления | Выбор из каталога и состояние конкретного экземпляра; EV отделяется от веса и ENC |
| Оружие и щит | Основное и запасное оружие, WA, урон/тип, надёжность, число рук, дальность, эффект, скрытность, улучшения; щит и его характеристики | Выбор предмета из каталога; текущая надёжность хранится отдельно от базовой |
| Снаряжение | Предметы, количество, заметки, вес, ценность, компоненты и переносимый вес | Выбор из каталога или собственный предмет; ссылки по постоянным ID, состояние принадлежит конкретному персонажу |
| Магия | Заклинания, знаки, инвокации, ритуалы, сглазы/проклятия, стоимость, эффект, дальность, длительность, время, СЛ, компоненты; Vigor и его модификатор | Разделы показываются по применимости. Названия и краткие свойства выбираются из проверенного каталога; неизвестное не подменяется расчётным значением |
| Заметки | Заметки, кампанийный журнал и дополнительные детали | Свободный текст |

## 3. Таблица вычислений и правил

Статус «можно автоматизировать» означает, что есть официальное правило/уточнение, позволяющее реализовать расчёт без выбора мастера. «Ожидает сверки» означает, что поле остаётся ручным в первом движке правил.

| Результат | Правило | Статус и источник |
|---|---|---|
| Порог STUN | Рассчитывается от BODY и WILL по таблице физических показателей; STUN ограничен значением 10. Для проверки STUN бросают ниже своего значения. | **Правило подтверждено errata и уточнением разработчика.** Перед кодированием значения для нечётной суммы BODY+WILL проверить по p. 47–48 русского экземпляра, потому что его таблицу сейчас нельзя прочитать. [Sage’s Answers, Part 18](https://rtalsoriangames.com/2018/09/21/the-sages-answers-part-18/), errata p. 47–48. |
| RUN и LEAP | RUN и LEAP — производные от SPD/RUN, определены на p. 47; LEAP задаёт прыжок и дистанцию подъёма. | **Ожидает прямой сверки формулы и округления** по p. 47 используемого издания. До этого вводить вручную. |
| HP, STA, REC | Берутся из Physical Table на p. 48 на основании BODY и WILL. | **Ожидает сверки значений таблицы и округления** по p. 48. Не использовать предположительные множители. |
| ENC и переносимый вес | ENC — показатель листа; конкретное влияние на нагрузку задаётся правилом p. 48. Вес предметов уже хранится в каталоге в кг. | **Ожидает сверки формулы ENC и единиц веса.** Не сравнивать ENC с килограммами, пока не подтверждено, что шкалы совпадают. |
| Punch, Kick и Bonus Melee Damage | Значения выбираются по таблице BODY на p. 48; бонус урона рукопашного боя уже учтён в Punch/Kick согласно примечанию таблицы. | **Ожидает сверки строк таблицы BODY** по p. 48. Пока отображать как ручные поля. |
| Vigor | Порог определяется профессиональными правилами. Сумма стоимости заклинаний за раунд сравнивается с ним; превышение имеет последствия по правилам магии. | Порог хранить как значение профессии/модификаторов, не вычислять из основных характеристик. Числа и исключения профессий сверить по описаниям профессий и магии. |
| Проверка навыка | Лист должен показывать рейтинг навыка, ведущую характеристику и применённые модификаторы раздельно. Итог броска и особенности критов/провалов внедрять после сверки раздела проверок. | **Ожидает прямой сверки** по p. 49–60 и актуальной errata. Не сводить все модификаторы в скрытое одно число. |
| Штраф EV брони | EV вычитается из REF и DEX (минимум 1); EV также учитывается для Hex Weaving, Ritual Crafting и Spell Casting. | **Можно автоматизировать после выбора активной брони.** Официальная errata p. 78. Вес предмета и EV — разные поля. |
| Потраченная LUCK | Игрок выбирает число очков до броска; каждое даёт +1 к проверке навыка или Death Save. Запас восстанавливается в начале игровой сессии. | **Можно автоматизировать как ресурс**, но восстановление — только по кнопке начала сессии. Официальная errata p. 47. |
| Нелетальный урон и STA | Нелетальный урон уменьшает STA, а не HP. STA также тратится на магию, дополнительные действия и некоторые защиты. При STA ≤ 0 персонаж теряет сознание; возвращение в сознание и выход из STUN подчиняются отдельным порогам и броску. | **Правило подтверждено официальным уточнением.** Автоматизировать уменьшение ресурса только после явного ввода действия/урона; не угадывать последствия конкретного эффекта. [Sage’s Answers, Part 18](https://rtalsoriangames.com/2018/09/21/the-sages-answers-part-18/). |
| Death State | При переходе в Death State характеристики и производные показатели временно уменьшаются; Death Save использует неизменённый STUN. | Учитывать отдельным режимом состояния, не перезаписывать постоянные значения. Официальная errata p. 162. Точный способ округления временных значений проверить до автоматизации. |
| Лимиты навыков/характеристик | Статистический лимит 10 с исключениями для мутаций и расовых особенностей. Начальный рейтинг навыка не выше 6; в развитии базовый предел 10. Расовые бонусы могут превышать его; бонусы жизненного пути не поднимают лимит. | **Можно использовать в проверке создания/развития** с отображением источника исключения. Официальная errata p. 23, 32, 47. |

## 4. Различия профессий

Официальный список включает девять профессий: Bard, Craftsman, Criminal, Doctor, Mage, Man at Arms, Merchant, Priest и Witcher. На листе это не декоративная метка: профессия определяет определяющий навык, профессиональное дерево/умение, набор навыков и стартовое снаряжение. Конкретные очки, предметы, ограничения и доступ к магии — данные соответствующей профессии, их не надо переносить в общие правила листа.

| Профессия | Особые данные листа |
|---|---|
| Bard | Профессиональное дерево и определяющий навык; отдельный магический блок не включать без соответствующего правила/выбора персонажа |
| Craftsman | Профессиональное дерево, ремесленные навыки, стартовые инструменты/снаряжение |
| Criminal | Профессиональное дерево, навыки скрытности/преступного ремесла, стартовое снаряжение |
| Doctor | Профессиональное дерево и лечебные навыки; фиксировать медснаряжение и лечение |
| Mage | Профессиональное дерево; раздел spells; магический Vigor и его модификатор |
| Man at Arms | Профессиональное дерево, боевые навыки, оружие и броня |
| Merchant | Профессиональное дерево, торговые навыки, стартовые деньги и товары |
| Priest | Профессиональное дерево; invocations, rituals/hexes, если доступны персонажу; магический Vigor |
| Witcher | Профессиональное дерево; signs, witcher potions/decoctions, мутации и связанная с ними токсичность согласно правилам |

Во всех профессиях общая форма листа остаётся одной. Профессиональные различия хранятся в справочных данных по версии правил: доступные поля, начальные навыки, дерево/умения, снаряжение, ресурсы и ограничения. Это позволит добавлять исключения без ветвлений UI по названию профессии.

## 5. Версионирование и сохранение

- Каждая запись персонажа имеет постоянный `characterId`, `schemaVersion` и `rulesVersion`.
- Статические ссылки на предметы используют ID каталога; если предмет изменён или удалён, запись персонажа сохраняет имя и вес как снимок, чтобы старое сохранение не теряло данные.
- Базовое значение, временное состояние и модификатор хранятся раздельно. Правила не должны менять базовую характеристику при ранении, Death State или снаряжении.
- Экспорт JSON содержит всю запись персонажа и версию схемы; импорт сначала проверяет её, затем запускает миграции. Неизвестные поля сохраняются при повторном экспорте либо явно сообщаются пользователю.
- Прежний отдельный инвентарь мигрируется в персонажа только с резервной копией JSON и проверкой количества/веса.

## 6. Условия закрытия спецификации

Перед включением автоматического расчёта для всех полей со статусом «ожидает сверки» нужны читаемые страницы из применяемого русского издания: создание персонажа и жизненный путь (20–46), характеристики и производные показатели (47–48), навыки и проверки (49–60), профессии/деревья умений (61–70). После получения страниц спецификация фиксирует точные формулы, округление, лимиты и переводы, затем добавляются контрольные примеры с рассчитанными вручную ожидаемыми значениями.
